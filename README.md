# 27Nuts 管理后台

Next.js 管理后台、原生微信 TypeScript 小程序、FastAPI API 和 MySQL，前后端独立部署。

## 启动

1. 复制 `.env.example` 为 `.env`，设置数据库密码、管理员密码（1至256位）和 JWT 密钥（至少32位）。数据库密码建议采用字母和数字，特殊字符需对 DATABASE_URL 做 URL 编码。
2. 执行 `docker compose up --build -d`。
3. 打开 http://localhost:3000，使用环境变量配置的管理员登录。API 文档：http://localhost:8000/docs。

MySQL 使用持久化卷。不要执行 `docker compose down -v`，它会删除数据库。
生产环境应设置实际 API 域名及 CORS_ORIGINS，以 HTTPS 反向代理暴露前后端；修改 NEXT_PUBLIC_API_URL 后重建前端。

## 已实现

- 管理员登录、8小时令牌、受保护的管理 API。
- 运营统计、玩家创建与搜索、玩家详情及积分流水。
- 常规赛和 GTO 赛事记分，事务发放积分和奖励，提交幂等。
- 手动调分（原因必填）、月榜与总榜、按月份保存积分。
- 奖励列表、补发、撤销、按码查询、原子核销，GTO两张门票独立核销。
- 切换当前月赛，历史积分不删除。
- 响应式中文界面、Docker Compose 部署。

## 业务约定

后台“奖品设置”管理奖品目录、启用状态、各名次发放奖品与份数（0–20）、可发放库存。新部署沿用原奖品规则，默认不限库存；实际库存由门店录入。GTO冠军的两种奖励方案均可配置，记分页面显示实际奖品与份数。手动补发可选择1–20份，每份独立生成核销码。

有限库存于发放时预占，核销不再次扣减；未使用奖励撤销时退回预占库存。库存不足时比赛结果、积分、奖励和场次状态一起回滚。旧奖励没有预占库存标记，撤销不会凭空增加库存。设置保存携带库存版本，发放或其他管理员修改后旧页面不能覆盖新库存，需刷新再调整。库存模式变化、补货调整、奖品发放及撤销退回记录在库存流水中。奖品行支持删除并填写原因：仍在比赛发奖规则中使用的奖品，须先替换或将发放数量设为0并保存；删除后从发放与兑换列表移除，历史奖励和库存流水保留，已发奖励仍可核销或撤销退库，旧页面不能恢复已删除奖品。新增未保存奖品可以直接在草稿中移除。升级需执行迁移 e85cb03f721a。修改名称和发放规则不改变已发奖励的记录。

月积分归属比赛日期；手动调整时指定月份。前三名不能重复，27收池可与前三名重合。V1奖励永久有效，管理员可撤销未核销奖励。核销码为10位随机十六进制字符串，保持全库唯一。榜单包括零分与负分玩家。月榜同分按最后正向获分时间升序，时间相同时按积分流水顺序；总榜同分按玩家编号。扣分不更新最后获分时间。

后台可以先创建线下玩家；小程序通过微信登录创建独立档案，不按昵称或公开会员号自动合并线下档案。线下旧档案绑定尚未实现。赛事暂不直接编辑，修正积分用反向流水、修正未使用奖励用撤销及补发，并填写原因。已核销记录不能删除。

## 微信小程序

### 小程序店员扫码核销

用户在“奖励 → 门票详情”出示二维码。店员从“我的 → 门店管理”进入，使用已有管理后台账号登录，点击“扫码门票”，核对玩家昵称、会员 ID、门票名称和状态后点击“确认核销此门票”。扫码仅查询，不自动核销；已核销或撤销的门票不能再次使用。每次只核销扫码对应的一张门票，操作管理员和时间沿用后台记录。

后台“玩家管理 → 玩家详情 → 微信管理员权限”可将已微信登录的会员设为管理员，也可取消权限。请按会员 ID 核对身份。授权需二次确认，拥有完整后台管理权限；并非仅能核销的角色。授权后，会员用原微信身份进入“门店管理”即自动通过权限校验，无需输入后台密码。撤销后，每次请求都会重新核验绑定关系，原微信凭证不能继续执行管理操作，普通会员登录仍保留。权限变更保存最近操作人及时间，历史核销操作对应的管理员记录继续保留。线下玩家未绑定微信时不能授权。

仍支持使用后台账号密码登录扫码，凭证独立保存，不覆盖微信会员登录；失效时会尝试当前微信身份。管理员内部权限相同，普通微信会员不能查询他人的门票或提交核销。

后端新增 `qrcode==8.2` 依赖，更新时安装 `backend/requirements-all.txt` 并重启 API，重新上传小程序；首次升级微信管理员授权功能必须先在 backend 目录运行 `python -m alembic upgrade head`，最新迁移为 `f96dc14a832b`，然后重启 API、重建 Web 管理后台并重新上传小程序。二维码在服务器生成矩阵，由小程序本地绘制，不向第三方发送核销码。扫码使用微信原生 `wx.scanCode`，必须在真机验证摄像头授权、实际二维码识别和核销结果。自动检查：`npm run typecheck:mini`、`node --test scripts/test-staff.cjs`、后端 `pytest`。

### 名次奖励与到店核销

门票与比赛名次绑定，管理员录入冠军、亚军、季军和选填的27收池后，积分与对应奖励在同一事务内直接发放到玩家账号，玩家在“奖励”中查看并出示二维码核销。积分用于月赛榜和总榜排名。小程序“我的 → 门店管理 → 赛事记分”使用管理后台账号登录，支持搜索昵称或会员 ID、已有进行中场次和独立赛事录入；重复提交不重复发奖。

默认规则：常规赛冠亚季军分别加5/3/1分，发常规赛门票/五折票/七折票各1张；27收池不加分，发常规赛五折票1张。GTO冠亚季军分别加10/6/2分，冠军选礼品1份或GTO门票2张，亚军发GTO门票1张、季军发GTO五折票1张；27收池不加分，发GTO五折票1张。后台“奖品设置”维护各名次的奖品、数量和库存。

积分兑换页面、入口及后台兑换价格设置已移除，旧版小程序调用 GET/POST `/mini/exchange` 返回410停用提示，不能扣分或发票。历史兑换流水和已发门票保留，未使用的历史门票仍可核销或由管理员撤销，撤销时沿用原退款及退库存逻辑。

后台“到店核销”支持搜索昵称或会员 ID，选择玩家、勾选待使用奖励、在页面弹窗内确认。每次最多100份，全部核验归属和状态后一起提交；其中任意一份无效则整批不核销。操作人和核销时间仍完整保存，核销不会再次扣库存或积分。

此次移除无需新数据库迁移；保留既有历史表和迁移。更新后端、重建管理后台并重新上传发布小程序后生效。后端测试覆盖停用兑换接口、各名次自动发奖、重试幂等、历史票退款及批量核销。

### 比赛场次与参赛名单

管理后台“比赛场次”创建场次（名称、常规赛/GTO、北京时间、人数上限3–500人），支持按日期查看。可提前创建未来场次，小程序只展示北京时间当天的场次，用户登录后加入或退出。重复加入不占额外名额，退出释放名额，满员时禁止新报名。

店员根据用户出示的会员 ID 在名单中确认到场，点击“开始比赛”关闭报名和退出；已报名玩家仍可由管理员确认到场。结果只能从本场已到场名单选择，至少三位不同玩家获得前三名；27收池可与前三名重合。比赛类型和积分日期由场次确定。成功提交后，记分、奖励和场次结束在同一事务保存；重复提交不重复发放。场次可在报名中或进行中取消，取消后不能恢复，历史报名记录保留。已结束场次不能取消或重新记分。

原“赛事记分”保留为独立手动记分入口，供历史或未创建场次的比赛使用。已创建场次的比赛应从“比赛场次”提交结果，避免另外录入一笔独立赛事。

微信开发者工具导入项目根目录，使用 project.config.json 中的 AppID。页面包括首页、当日比赛、月榜/总榜、奖励中心、我的、登录和奖励详情；后台积分与奖励直接同步，只有管理员可以核销奖励。

服务端 .env 配置 WECHAT_APP_ID 和 WECHAT_APP_SECRET，再重启 API（Docker 方式重建 API 容器）；AppSecret 只放服务端。未配置时登录返回明确提示，不使用模拟微信身份。miniprogram/services/api.ts 根据微信环境选择接口：开发版使用 http://127.0.0.1:8000，供电脑微信开发者工具测试；体验版和正式版使用 https://nuts.fateinsight.site/api。电脑本地测试需在开发者工具中勾选不校验合法域名及 HTTPS 证书。手机真机连接本地服务时需改为电脑局域网 IP 并开放相应端口，手机上的 localhost 无法访问电脑。发布环境须在微信平台配置 request、uploadFile、downloadFile 合法域名及隐私声明。

首次打开小程序进入会员注册页。用户阅读并同意说明后，通过微信 `chooseAvatar` 主动选择头像，通过 `input type="nickname"` 选择微信昵称或填写自定义昵称，再提交注册。不是静默读取微信资料。服务端校验微信身份后一并保存昵称、头像和同意时间，同一 OpenID 不会重复建档；已有会员可直接微信登录，历史会员缺少资料时补全。昵称和头像可在“我的”页修改，后台玩家列表和详情展示头像。

头像使用 `wx.uploadFile` 上传，限制5MB，支持 JPG/PNG/WebP，服务端重新编码为256像素 JPEG。上线时除 request、downloadFile 外还要配置 uploadFile 合法域名，并在微信后台填写实际用户隐私保护指引。页面中的说明不替代平台隐私配置。头像保存在 backend/uploads/avatars；Docker 使用 avatar-data 持久化卷，备份时同时保存数据库与头像卷。新增资料字段通过 Alembic 迁移保留原有会员、积分和奖励。

两张黑金原图由 API 的 /assets/mini/brand.png 和 /assets/mini/rewards.png 提供，避免放入小程序包。图1的固定卡片和图6的固定20行榜单作为设计参考，实际卡片与榜单由代码动态渲染。

执行 npm run typecheck:mini 验证 TypeScript（需要先安装 frontend 依赖）。服务端测试覆盖微信身份重复登录、管理员/玩家权限隔离、奖励归属和核销后隐藏核销码；测试替换微信换码服务，不能替代真实微信登录验收。发布前还须在微信开发者工具与真机验证页面、安全区、素材加载及真实登录。

## 本地开发与验证

本地环境使用 Node.js 22 和 Python 3.10+；Docker 已固定使用 Node.js 22、Python 3.12、MySQL 8.4。

后端：创建虚拟环境，`pip install -r backend/requirements-all.txt`；设置 DATABASE_URL、JWT_SECRET、ADMIN_PASSWORD 后，从 backend 先运行 `alembic upgrade head`，再运行 `uvicorn app.main:app --reload`。
前端：`cd frontend && npm ci && npm run dev`，NEXT_PUBLIC_API_URL 默认 http://localhost:8000。
测试：从 backend 执行 `.venv/bin/python -m pytest -q`。设置 TEST_DATABASE_URL 可在**专用测试 MySQL 数据库**执行同套测试（测试会删建表，禁止指向业务数据库）。
构建：`cd frontend && npm run typecheck && npm run build`。

Docker API 启动先执行 Alembic 数据库迁移，再初始化管理员；后续启动不覆盖密码。新增数据库结构须创建并审查迁移文件，禁止对存量数据盲目重建。上线前备份数据库，并确认所在环境的域名、HTTPS 与账号配置。

## 管理员维护

部署后新增管理员：`docker compose exec api python -m app.manage create-admin staff`。
重置密码：`docker compose exec api python -m app.manage reset-password admin`。
命令交互输入密码，不回显；重置后原有令牌失效。连续5次错误密码将锁定该账号15分钟。
所有赛事、积分流水与核销时间统一按 Asia/Shanghai 存储和展示。奖励撤销保留原始发放原因，另存撤销原因及操作人。

前端操作测试：`cd frontend && npm test`，覆盖登录失败、GTO赛事发放与单张奖励核销。组件测试使用模拟 API；后端业务测试独立连接 MySQL。

## 部署验证与备份

服务启动后，在仓库根目录执行 `backend/.venv/bin/python scripts/smoke.py`，验证通过 Next.js 代理的健康检查、权限及各管理接口（从本地 `.env` 读取账号，不输出密码或令牌）。
备份数据库：`docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction nuts' > nuts-backup.sql`。备份文件应放在安全位置，升级前先完成备份。
